# python — библиотека и GUI для лидара Ecovacs FM1828

Python 3.10+, зависимость только `pyserial`. Железо: ESP32 с прошивкой `firmware/bridge`
(прозрачный мост USB ↔ лидар, 460800), лидар TX → GPIO16, RX ← GPIO17, GND общий, VCC 5 V.

```sh
/tmp/floorbot-lidar-py312/bin/python -m fm1828 --port /dev/cu.usbserial-10 --seconds 10     # статистика по оборотам
/tmp/floorbot-lidar-py312/bin/python fm1828_gui.py --port /dev/cu.usbserial-10                # живой GUI: http://127.0.0.1:8765
/tmp/floorbot-lidar-py312/bin/python fm1828_gui.py --replay ../captures/fm1828-spin-15s.bin
/tmp/floorbot-lidar-py312/bin/python restart_test.py --port /dev/cu.usbserial-10             # тест повторного запуска (нужен свежий цикл питания)
```

Из корня проекта конфигурации для панели браузера: `.claude/launch.json` → `fm1828-gui-replay` (порт 8765), `fm1828-gui-live` (порт 8766).

## Библиотека `fm1828`

- `protocol.py` — описание протокола и `StreamParser`: принимает сырые байты, отдаёт кадры `Frame`, кадры простоя и собранные обороты `Scan` (список `(угол°, мм)`), считает ошибки контрольной суммы, пропуски кадров, мусор.
- `driver.py` — `SerialSource` (порт открывается без сброса ESP32), `ReplaySource` (воспроизведение дампа в реальном времени), `FM1828` (фоновый поток чтения, `start_motor()` = `$` → 2 с → `startlds$`, `stop_motor()` = `stoplds$`, `status()`).
- `angle_of(idx, point)` — угол точки: кадр 0xA0…0xF9 по 4°, 16 точек по 0.25°.

Аналогичный драйвер для ESP32: `arduino/FM1828` (Arduino/PlatformIO), демо `firmware/demo`.

## GUI

Сервер отдаёт страницу, поток оборотов по Server-Sent Events (`/events`), `/api/status`, `POST /api/start|stop|raw`.
Страница рисует полярный скан и карту занятости (сетка вокруг неподвижного лидара: трассировка луча помечает
свободные ячейки, точка попадания — занятую; «Память карты» задаёт затухание). Регуляторы: дальность, поворот нуля,
зеркалирование, размер ячейки. Одометрии нет, поэтому это карта окружения с места, а не SLAM.

## Известные ограничения лидара (см. `../docs/protocol.md`)

- `startlds$` первой командой после открытия порта игнорируется; сначала нужен `$`.
- После `stoplds$` повторный запуск не принимался до переподачи питания (наблюдалось в двух циклах питания). Для
  робота нужен управляемый ключ 5 V на лидар либо не останавливать мотор командой. `restart_test.py` уточняет это.
- Направление нуля и сторона вращения относительно корпуса не откалиброваны.

## Перезапуск после остановки

Из прошивки DEEBOT T9 AIVI 1.4.9 (`../docs/firmware-analysis.md`) известны все команды лидара: `startldspl$startlds$`
(«plus startup», робот шлёт при старте), `startlds$`, `stoplds$`. Других нет; питание лидара в роботе коммутирует MCU
(`lds_power: %d` в прошивке MCU).

Наблюдения на FM1828:

- `startldspl$` запустил лидар из состояния «молчит» (нет кадров простоя) с ответом 0x21 — так же, как первый `$` после включения.
- Сразу после `stoplds$` лидар шлёт кадры простоя и не принимает ни `startldspl$`, ни `startlds$`, ни их комбинации;
  break на линии RX (TX моста в нуле 5 с) и 2000 нулевых байт тоже не сбрасывают его.
- Через 11–16 минут после `stoplds$` без команд лидар сам замолкает (засыпает) и снова принимает `startldspl$` — проверено дважды.
  Идёт проверка, воспроизводится ли этот таймаут (`idle_timeout_test.py`, лог пишется в файл, указанный аргументом).
- Дизассемблирование драйвера робота (`../docs/firmware-analysis.md`): `stopLds()` = `stoplds$` **плюс снятие питания через MCU**,
  `startLds()` = включение питания, затем `startldspl$startlds$`. Робот не перезапускает лидар без цикла питания, значит
  на FM1828 это штатное поведение, а не ошибка команды.

`FM1828.start_motor()` теперь шлёт `startldspl$`, а если за 3 с нет кадров — `$` и `startlds$`. `restart()` = `stoplds$`, пауза, старт.

### Запасной вариант: ключ питания

Если программный перезапуск не подтвердится, мост умеет управлять ключом 5 В на GPIO4 (высокобоковой P-MOSFET или
модуль реле; рвать +5 V, не GND): служебные последовательности `\x01PWRCYCLE\x01`, `\x01PWROFF\x01`, `\x01PWRON\x01`
не пересылаются лидару; в Python `FM1828.hard_restart()`, в C++ `setPowerPin(4)` + `hardRestart()`.
При выключении GPIO17 держится в нуле, чтобы не подпитывать лидар через RX.
